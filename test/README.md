# Description link regression tests

Run `pnpm test` after the normal locked dependency installation. Tests use Node's
built-in test runner (Node 20+), the declared TypeScript compiler in memory, and
the actual Turndown/Martian packages. No new test dependency, emitted source,
browser, token, or live Canvas/Notion service is needed. The export integration
test substitutes Storage and the Notion client and inspects actual page-create
parameters generated by `exportToNotion`.

`fixtures/issue-344.html` is the unchanged redacted `description` from
https://github.com/JamesNZL/notion-assignment-import/issues/344#issuecomment-2036034105.
It contains seven fragment links and six absolute Canvas links. Tests retain the
original HTML, including custom styles and markup.

Policy exercised by the current version:

- Resolve fragment/path/query/protocol-relative hrefs using a validated absolute
  HTTP(S) assignment URL before Markdown parsing. They point back to Canvas;
  HTML IDs are not mapped to Notion block IDs.
- Retain HTTP(S) destinations without userinfo and nonempty, non-authority mailto
  and tel destinations. Keep GFM bare-email mailto links too. Only absolute HTTP(S)
  URLs can serve as the Canvas base; mailto/tel bases never resolve relative hrefs.
  Unsupported schemes such as ftp/javascript/data become visible formatted text.
- Trim boundary whitespace, reject embedded ASCII controls/backslashes,
  preserve literal percentages and existing escapes without blanket re-encoding,
  serialize Unicode/spaces with the standard URL API,
  and enforce 2000 characters on the final serialized destination. Never truncate
  a URL. Absolute HTTP(S) links still work with a missing/invalid assignment base.
- Protect Markdown destinations with angle brackets and entity escaping so
  parentheses, query ampersands and already encoded values keep their meaning.
- Only pure inline anchor content is wrapped in a Markdown link label. Empty
  destinations preserve adjacent inline emphasis when href is absent/invalid.
- Unwrap block/media anchors with absent/invalid href while preserving blocks,
  image URLs, visible text, annotations and independent inner links. For valid
  structural hrefs, work on a DOM clone and distribute the destination to inline
  text without enclosing block/media Markdown in a link label. Block boundaries
  survive whitespace trimming. Media and preformatted code blocks themselves
  have no wrapper hyperlink mapping. An ordinary inline line break remains a
  valid link label; a newline alone never triggers structural unwrapping.
- Recursively check rich text produced by Markdown (including GFM autolinks),
  nested children, table cells and captions. The synthetic table/caption case
  checks this defensive boundary; Turndown's table/media conversion is unchanged.
- Leave image/external media URLs, export retries and API versions unchanged.

V2 repairs two compatibility regressions identified by the user's real API
review: supported mailto/tel links had been stripped, and literal `%ZZ` had been
rejected even though the API preserves it. Live acceptance and semantic readback
are recorded separately from this offline suite; HTTP 200 alone is insufficient.

V3 repairs v2's block/media anchor regression. Tests assert explicit source
semantics (block types/order, text, image URL and formatting) across id/name,
empty, malformed, unsupported and supported href wrappers; comparison with the
unwrapped legacy converter is supplementary, not the only oracle. The three
independent review counterexamples also exercise real export-create parameters.
No fake URL or invisible text marker is used, and media URLs are not rewritten.
V3 r2 also retains links on multiline inline labels and text adjacent to media;
the r1 review snapshot remains separate evidence. General Martian rendering
limitations, such as an image nested inside a bold Markdown span, are outside
this link fix and are recorded separately rather than counted as semantic passes.

Check `pnpm run build`, `pnpm exec tsc --noEmit -p src/tsconfig.json`, and
`pnpm exec eslint src/popup/description.ts src/popup/import.ts test/description.test.cjs`.
The full source lint currently has pre-existing errors in `src/apis/notion.ts`
and `src/types/notion.ts`; this patch does not reformat those files.
